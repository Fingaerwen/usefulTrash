## Building the spike
1. `.env` (repo root, git-ignored) holds `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` and `GOOGLE_WEB_CLIENT_ID` (see `.env.example`).
2. `python3 spikes/phase0/makePublicConfig.py` copies exactly those three public values into `spikes/phase0/src/publicConfig.json` (git-ignored). It refuses missing or malformed values and anything that looks like a secret, and never prints values.
3. `cd spikes/phase0 && ../../.venv/bin/flet build apk --yes` builds `build/apk/phase0.apk`, signed with the debug key (SHA-1 `57:92:1B:25:A7:0A:93:21:E8:2A:EA:45:A8:97:B3:3F:10:CC:29:D2`, registered in Google Cloud's Android client).
4. `adb install -r build/apk/phase0.apk` installs it over the old version (data and the weekly alarm are kept).
5. PC view (check 6): `cd spikes/phase0 && ../../.venv/bin/flet build web --base-url /usefulTrash/ --no-cdn --yes` builds the website into `build/web` (served from `/usefulTrash/` on GitHub Pages, `--no-cdn` ships Python and Flutter from our own site instead of a public CDN).
6. **Pitfall:** after changing an extension's `pubspec.yaml`, delete `spikes/phase0/build/flutter/.dart_tool/package_config.json` before building. Flet copies the extension in after Flutter's dependency step and doesn't re-run it, so the old settings would be used (seen 2026-10-12: "The 'inline-class' language feature is disabled" although the minimum Dart version had been raised).
